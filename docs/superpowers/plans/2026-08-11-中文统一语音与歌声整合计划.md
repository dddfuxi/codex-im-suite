# 中文统一语音、语气与歌声整合计划

## 1. 目标

把当前分散的“普通说话、语气控制、参考音色复刻、歌词演唱”整理为一套一致的用户体验：

- 用户只维护一个长期音色条目，同一音色可分别用于说话和唱歌。
- 中文文本按原文说，中文歌词按原文唱；不能把普通 TTS、朗诵、MP3 附件冒充歌声。
- 说话支持语气/情绪/速度，唱歌支持完整歌词、自动或显式旋律、风格和时长。
- 面板明确区分“10 秒快速试听”和“按完整内容生成”，不再把试听限制误解为正式能力限制。
- 飞书回执分别显示“已生成、已发送、音色相似度通过、歌词对齐通过”，任何未过门禁的结果不得显示成功。
- Provider、模型和能力必须由声明式 Manifest 驱动；不得为某一句话、某个机器人或某个音色写死分支。

## 2. 当前现场结论

### 2.0 实施状态（2026-08-11）

- [x] 阶段 0：完整歌词、风格、语言、自动旋律、可选时长、10 秒快速试听与完整生成已进入开发版；可靠原生回复歌词可直接形成受限歌声计划。
- [x] 阶段 1：Provider capability、统一音色分模式验收、内容计划、生成回执已同步到 Contract、JSON Schema、Runtime、Core、C# 和 Web。
- [ ] 阶段 2：Vevo2 仅登记为 `experimental / blocked`。逐文件 Hash、固定 Runtime、RTX 3070 benchmark 和许可审查未完成前，不下载、不安装、不启用。
- [ ] 阶段 3：现有受管参考音色已支持说话/歌声独立验收；Vevo2 重验与跨 Provider 迁移等待阶段 2。
- [ ] 阶段 4：开发版面板与 Feishu/Core 交付路径已实现，尚未同步 live、重启或用重启后的真实飞书新消息验收。
- [ ] 阶段 5：没有替换或删除 Qwen3-TTS、ACE-Step、现有音色与 benchmark；默认 Provider 切换条件尚未满足。

当前可交付实现是统一 UI/Contract 下的 `Qwen3-TTS + ACE-Step 1.5` 双 Host。Vevo2 只是候选 PoC，不把“目录已展示”描述成“模型已接入”。

### 2.1 截图中的失败不是 ACE-Step 生成失败

“用克隆音色唱”在进入真实 `SingingHost` 前，因 Primary 没有返回合法 `cti-final.singing` 指令而失败。当前审计只证明协议修复没有成功，不能据此判定 ACE-Step 的生成质量。

### 2.2 当前实现确有产品能力缺口

- 面板字段直接写成“试听歌词（固定 10 秒）”。
- `createSingingVoicePreview()` 把风格固定为“清晰自然的中文流行人声，简洁伴奏”，时长固定为 10 秒。
- 正式歌声协议虽然支持最多 6000 字歌词和 10–600 秒时长，但面板没有“完整生成”入口，也没有旋律来源、情绪/风格和预计时长设置。
- 明确唱歌请求仍依赖模型正确组装完整 JSON 协议；即使歌词来自唯一可靠的原生回复，协议修复失败后也会在 Host 前结束。
- 说话相似度通过不等于唱歌相似度通过。两种模式必须分别评估，不能复用一个布尔值伪造成功。

## 3. 组件选型结论

### 3.1 首选：Amphion Vevo2（可选 Provider、先 PoC）

选择理由：

- 同一框架原生覆盖 zero-shot TTS、Text-to-Singing、SVS、VC/SVC、歌声编辑、歌声风格转换和旋律控制。
- 模型把内容、风格/韵律和音色分离，适合把同一授权参考音色用于说话和唱歌。
- 官方示例包含中文目标文本，模型仓库标注 6 种语言；训练同时使用大规模语音与歌声数据。
- AR 主体约 0.5B，另有 350M Flow 模型、250M Vocoder 和两个 tokenizer；规模比 130B 级端到端语音模型更适合先在 RTX 3070 上验证。

必须保留的限制：

- 官方没有给出 RTX 3070 8GB 的显存和速度承诺，必须以本机 benchmark 为准。
- 模型权重许可为 `CC BY-NC-ND 4.0`，只适合先做本机非商用 PoC；任何商业使用必须先完成许可审查。
- Vevo2 的“语气”主要来自 style/prosody reference 与转换能力，不应虚构成任意中文情绪标签都能稳定命中。需要建立受管语气参考库并单独验收。
- 官方脚本会自动下载权重；Suite 集成时必须禁用自动下载，改为显式安装、固定 revision、逐文件 Hash 和事务发布。

### 3.2 不作为本轮主替代的候选

| 候选 | 优点 | 不选为统一主组件的原因 |
|---|---|---|
| Step-Audio TTS 3B | 中文、零样本克隆、情绪/语速/方言，最低显存标称 8GB | 官方能力重点是说话、rap 和清唱式哼唱，不是完整歌词到歌曲；旧仓库已停止维护并指向新系列，Linux 为主要测试环境 |
| Ming-omni-tts | 中文零样本克隆、情绪、语速/音高/音量控制，并能生成 BGM/环境声 | 官方没有声明歌词演唱；“说话与音乐同轨”不等于可控 singing，且示例测试硬件是 H800/H20 |
| SoulX-Singer | 中文/英文/粤语、零样本歌声音色、歌词编辑、MIDI/F0 控制，Apache-2.0 | 是专用歌声模型，不负责普通说话和说话语气；可作为商业许可优先时的双引擎歌声备选 |
| UniVoice | 0.3B、同一参考音频统一说话与唱歌，方向最理想 | 论文当前仍写“将发布”代码和 checkpoint，尚不能作为可安装依赖 |

### 3.3 迁移原则

不把“统一体验”错误实现成“所有请求强塞给一个进程”。低延迟说话与长耗时歌声在生命周期、GPU 占用、取消和验收上不同，仍需保持独立 Host；统一的是 Provider 能力协议、音色资产、面板入口和最终回执。

Vevo2 先以 `experimental` Provider 并行接入。只有本机中文说话、语气、歌词、歌声相似度、性能和飞书原生投递全部通过，才允许把它设为默认。Qwen3-TTS 与 ACE-Step 在迁移期继续作为可回退 Provider，不能先删后测。

## 4. 目标架构

### 4.1 声明式 Provider 能力

新增浏览器安全的 Provider capability 描述，不在面板硬编码模型名：

- `speech.text`
- `speech.emotion`
- `speech.prosody_reference`
- `singing.text_to_singing`
- `singing.melody`
- `singing.voice_conversion`
- `voice.zero_shot_clone`
- `voice.cross_mode_identity`

Runtime 根据 Manifest 和真实 benchmark 返回状态；Core 只按稳定能力裁决，不识别 Vevo2、Qwen 或 ACE-Step 的私有参数。

### 4.2 统一音色资产，分模式验收

长期 `VoiceProfile` 保留一个稳定 Profile ID，但增加分模式状态：

- `speechAcceptance`：参考文本一致性、说话人相似度、模型/revision/硬件绑定。
- `singingAcceptance`：歌词内容对齐、歌声说话人/歌手相似度、模型/revision/硬件绑定。
- `styleReferences`：可选的受管语气/韵律参考，只改变风格，不改变音色身份。
- `capabilities`：由真实 Provider 验收决定，不再因为 `reference` 身份就直接宣称同时支持 speech/singing。

原参考录音、歌声参考和语气参考都继续进入受管音色目录；面板可删除，但删除前必须展示影响并同步清理对应 benchmark。

### 4.3 通用内容规划，不依赖固定句子

新增纯策略 `AudioContentPlanner`：

1. 识别明确模式：说话、朗诵、rap、清唱、带伴奏演唱。
2. 解析内容来源：当前消息、唯一可靠原生回复、用户明确附件或 Primary 生成的歌词。
3. 保留用户原文；只有用户要求创作时才允许改写歌词。
4. 风格、情绪、时长和旋律缺失时使用受控默认值；默认值来自 Manifest/设置，不按关键词写死。
5. 明确唱歌且歌词来源唯一时，Bridge 可直接形成受限执行计划；Primary 只补创意字段，不再承担整段协议必须一次写对的脆弱职责。
6. 多个强引用、歌词来源不完整或版权边界不清时失败关闭并说明缺项。

### 4.4 歌声输入模型

正式生成支持三种旋律模式：

- `auto`：只给歌词，Provider 自动生成演唱韵律；适合“把这段唱出来”。
- `reference_audio`：用户提供哼唱/演唱作为旋律与节奏来源。
- `midi_or_f0`：用户提供 MIDI 或 F0，严格控制音高和节奏。

快速试听仍固定为 10 秒，但只能显示为“10 秒快速试听”；正式生成根据歌词长度估算时长，并允许用户覆盖。时长估算是通用策略，不把某一句歌词绑定到固定秒数。

### 4.5 生成后验收与唯一终态

歌声必须依次通过：

1. 安全文件、格式、时长、大小、Hash 门禁。
2. 中文歌词对齐门禁；纯人声可直接 ASR，对带伴奏结果先使用受管人声 stem 再校验。
3. 歌声音色相似度门禁；阈值与说话阈值分开记录。
4. 显式 MIDI/F0 请求的旋律对齐门禁。
5. 飞书原生 `audio` 上传和发送回执。

最终回执分别显示：

- `内容已生成`
- `原生语音已发送`
- `音色相似度已通过`
- `歌词对齐已通过`

任一步失败只投递一次完整文字终态；不得既发失败卡又补发音频，也不得把“已生成”显示成“已发送”。

## 5. 控制面板整合

### 5.1 用户区

- 一个“当前音色”选择器，显示说话/歌声两个能力徽标及各自验收状态。
- 模式：`说话 / 朗诵 / Rap / 清唱 / 带伴奏演唱`。
- 内容输入：说话文本或完整歌词，多行编辑，不再只有单行 10 秒字段。
- 语气/风格：Provider 支持的受管选项；不支持时明确禁用，不伪造。
- 旋律：自动、参考音频、MIDI/F0。
- 两个动作：`10 秒快速试听`、`按完整内容生成`。
- 完整生成显示真实阶段、取消按钮、耗时、GPU 状态和四项终态回执。

### 5.2 高级区

- Provider 选择和能力矩阵。
- 每模式 benchmark、峰值显存、实时率和最近验收时间。
- 模型安装、revision、许可标签和磁盘大小。
- Qwen/ACE-Step/Vevo2 的并行状态；切换失败时保留原默认，不先行写入成功状态。

## 6. 分阶段实施

### 阶段 0：先修当前可观察问题

- 把“试听歌词（固定 10 秒）”改成“10 秒快速试听歌词”。
- 面板增加完整歌词编辑和正式生成入口，试听与正式生成使用同一内容规划核心。
- 修复明确唱歌请求的协议收口：可靠歌词来源存在时不再因 Primary 漏写整个 JSON 而在 Host 前失败。
- 增加“协议未形成 / Host 未启动 / 模型生成失败 / 验收失败 / 平台发送失败”的独立诊断码。

### 阶段 1：Provider 与 Contract 抽象

- 新增 capability manifest、统一音色模式验收和 `AudioContentPlan` Contract/Schema。
- Runtime、Core、C# DTO、Web view-model 和边界测试同步更新。
- 保持现有 Qwen/ACE-Step 行为不变，先证明抽象没有回归。

### 阶段 2：Vevo2 隔离 PoC

- 固定 Amphion commit、Python/CUDA 版本、推理所需权重文件、大小和 SHA-256。
- 排除 optimizer、trainer state 等非推理文件，不采纳官方自动下载行为。
- 建立独立 loopback Sidecar、随机临时 token、单 Worker、受管 scratch 和强制取消。
- 在 RTX 3070 上分别测 10 秒中文说话、情绪/风格、自动旋律演唱、参考旋律演唱和同音色跨模式一致性。
- PoC 未通过前不写入普通用户默认选项。

### 阶段 3：统一音色迁移

- 现有 reference Profile 不复制用户 ID 或路径，只复用受管参考音频和稳定 Profile ID。
- 对 Vevo2 重新做参考文本检查、speech similarity 和 singing similarity；旧 Qwen benchmark 不能直接继承。
- 面板显示每个 Provider/模式的独立状态，并支持随时删除。

### 阶段 4：面板与飞书正式接入

- 上线完整内容编辑、风格、旋律、时长、生成、试听和取消。
- 飞书“把这个唱出来”继承唯一可靠回复正文；“用克隆音色唱”要求当前 Profile 的 singing 验收通过。
- 原生 Ogg/Opus exactly-once 投递，完整回执分项呈现。

### 阶段 5：切换与退役判断

- Vevo2 全部门禁通过后才允许设为默认统一 Provider。
- 若 Vevo2 在 8GB 显存、中文歌词或许可上不通过，则保留统一 UI/Contract，生产实现改为 Qwen3-TTS + SoulX-Singer 双引擎；用户体验仍是一套音色库。
- ACE-Step 只有在替代链路完成完整歌曲、中文歌词、克隆歌声和飞书现场验收后才进入可卸载状态。

## 7. 验收标准

### 7.1 中文说话

- 参考文本 ASR 逐字一致，否则禁止克隆。
- 用户文本不得被模型擅自改写。
- 中性、开心、悲伤、严肃至少四种受管语气可观察区分。
- 同一 Profile 在每种语气下均通过说话人相似度阈值。

### 7.2 中文唱歌

- “把这段唱出来”真实使用可见歌词，而不是朗诵或固定测试句。
- 10 秒快速试听和完整生成都能播放，二者标签与回执不同。
- 自动旋律、参考旋律和 MIDI/F0 至少各有一个真实样例通过。
- 生成后中文歌词对齐、歌声音色相似度和格式门禁全部通过。
- 普通 TTS、rap 朗诵或附件不得被误报为唱歌成功。

### 7.3 性能与运行态

- RTX 3070 真实记录冷启动、热态耗时、峰值显存、输出时长和实时率。
- Qwen、Vevo2、ACE-Step/SoulX 不得同时无界常驻 GPU。
- 取消必须 exactly-once，模型进程、任务和临时文件全部收口。
- 模型不可首请求隐式下载；安装失败不破坏旧 Provider。

### 7.4 飞书现场

- 重启后新 PID/runId、长连接正常、开发/live Hash 一致。
- 新消息分别复测：普通说话、带语气说话、按引用歌词唱、用克隆音色唱、取消、强制模型失败。
- 成功必须有真实原生 `audio` 平台回执；失败只出现一次文字终态。

## 8. 风险与回退

- **许可风险**：Vevo2 权重为非商用许可；许可不满足时不能作为生产默认。
- **显存风险**：官方未提供 8GB 结论；PoC 必须允许失败，不通过时切换双引擎方案。
- **中文歌词风险**：有中文字例不等于所有中文歌唱稳定；必须用真实歌词 CER/对齐验收。
- **语气控制风险**：风格参考与自然语言情绪指令不是同一能力；UI 只展示真实可用项。
- **音色风险**：说话参考音频可能缺少歌唱音域；singing similarity 必须单独测，必要时让用户追加授权歌声参考。
- **回退**：任何新 Provider 失败都回到旧 Provider 选择，不迁移或删除原音色、benchmark 和受管音频。
