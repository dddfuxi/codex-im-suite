# 表情包语义进化与回滚 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让飞书表情包基于真实发送与绑定反馈持续优化使用语义、范围化偏好和结构化避免规则，并保证每次机器状态变化都同步更新可回滚的人类可读档案。

**Architecture:** Bridge Core 只定义 delivery/feedback evidence、Host 协议和确定性绑定，不持有记忆根路径；Bridge Runtime 作为语义主库、revision、反馈分类、Prompt section 和中文档案的唯一写入者。Feishu adapter 只提供真实平台证据并消费可发送决策，控制面板只通过 runtime CLI Gateway 读写，不再直接修改 `stickers.json`。

**Tech Stack:** TypeScript/Node.js 20、Node test runner、JSON-only LLM classifier、C# .NET 9、React 19/Vite、UTF-8 Markdown/JSON/JSONL、原子文件事务。

- [x] **Step 3: 实现失败关闭绑定纯函数**

```ts
export function bindStickerFeedbackCandidate(input: StickerFeedbackBindingInput): StickerFeedbackCandidate | null {
  const referencedId = input.inbound.nativeReplyMessageId || input.inbound.reactionTargetMessageId;
  if (!referencedId) return null;
  const delivery = input.deliveries.find((item) =>
    item.outboundMessageId === referencedId
    && item.chatId === input.inbound.chatId
    && item.channelType === 'feishu');
  if (!delivery) return null;
  const evidenceId = hashFeedbackIdentity(input.inbound.eventId, referencedId, input.inbound.senderId);
  if (input.seenEvidenceIds?.has(evidenceId)) return null;
  return toFeedbackCandidate(input.inbound, delivery, evidenceId);
}
```

只接受原生 reply/reaction 字段和 runtime 查询出的 delivery；普通近邻、历史文本、模型输出 fileKey/messageId 均不参与绑定。
